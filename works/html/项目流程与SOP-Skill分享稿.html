上下五千年项目流程与 SOP / Skill 分享稿

本稿目的：同步近期整理和新增的 SOP 与 Skill，说明每个节点在做什么、对应哪份 SOP / Skill、上下游怎么衔接。

阅读方式：第一部分看整体流程图；第二部分按时间线逐节点看具体分工；第三部分对齐通用规则；附录留作 SOP / Skill 快速查阅入口。

一、项目全景

主流程五步 + 一条阶段性辅线（文献溯源）如下。辅线由主流程节点触发，为后续写作提供史料支撑。

二、按时间线走的工作节点

以下按主流程顺序，把每个节点讲清「什么时候启动、对应哪份 SOP 和 Skill、产出什么、和上下游怎么衔接」。有 Skill 内部有阶段划分的，一并说明。

故事选取

大纲简案

对应 SOP

对应 Skill

核心产出

SOP 与 Skill 分工

教研·AI大纲制作SOP.md 规定选故事在整个流程中的位置：先选集 → 再简案 → 再文献溯源前置 → 最后完整大纲。它同时约束一条：故事方案没有确认前，不要提前深化分集梗概。

select-history-stories（故事选取） 负责这一节点的执行本身，内部分两个阶段：

  • 阶段 A · 独立选材：Codex 自行读取项目定位、SOP 和秦汉定稿参考，建立故事候选池，产出按一级、二级、三级排列的推荐清单。这一阶段不读取、不讨论 IMA 结果，用于保证独立性；完整候选池通常 30–45 个，一级推荐固定 12 主选 + 3 备选。
  • 阶段 B · 交叉比较：独立清单锁定为快照后，再读取 IMA 清单。规范化两份清单的别名和故事颗粒度，比较重合、独有、替换、合并、拆分，产出最终故事方案。

上下游衔接：无上游 Skill；下游是 write-outline-brief（大纲简案）。故事方案由人工确认后才能进入下一节点。

节点 2

大纲简案

大纲简案
启动时机
12 集故事方案已经人工确认（选集冻结基线）。
对应 SOP
教研·AI大纲制作SOP.md
对应 Skill
write-outline-brief（大纲简案）
核心产出
大纲简案 0.0 → 1.0 → 2.0 → 3.0 → 【终稿】（版本链见第三部分）。
关键交叉点
简案定稿后立即触发辅线一——文献溯源初版启动。
SOP 与 Skill 分工

SOP 层规定简案回答的核心问题是「这个 SKU 整体怎么讲」——不是把每集写细，而是建立时代特征、SKU 整体教学目标、编排思路和 12 集简表。

write-outline-brief（大纲简案） 继承已确认的 12 集故事方案，主要做四件事：

  • 校准时代特征（要求由 12 集共同支撑，不另起脱节主题）；
  • 撰写 SKU 整体教学目标（知识、能力、情感与价值观）；
  • 撰写编排思路（3–5 段说明 12 集怎么串成因果链）；
  • 用简案颗粒度整理 12 集框架表（时期、集数、标题、时间、主要情节——背景/经过/结果三段）。

它不重新选故事、不展开每集完整梗概。人物、典故数量在简案阶段做暂定统计（「约 X 位」「X 余位」），不作为选集配额。

大纲简案阶段的情感目标从故事的自然落点反推，主要用于确定 SKU 整体的情感目标方向和编排意图，不要求 12 集每集单独配置情感目标。

上下游衔接：上游是 select-history-stories（故事选取）；下游同时衔接 write-source-tracing（辅线一的启动）和 write-outline-framework（完整大纲，需等文献溯源前期锁定后启动）。

节点 3

文献溯源初版 & 前期锁定

文献溯源
启动时机
大纲简案定稿后立即启动，作为完整大纲的史料底稿。
对应 SOP
文献溯源协作SOP.md
对应 Skill
write-source-tracing（文献溯源初版）；教研审核阶段人工为主。
核心产出
{SKU名}-文献溯源0.0.md + 自查报告 → 教研校准后形成 {SKU名}-文献溯源1.0.md（文内标注「前期锁定版」）。
关键交叉点
前期锁定版是完整大纲框架 0.0 的主要史料输入，未形成前不启动完整大纲。
SOP 与 Skill 分工

文献溯源协作SOP.md 规定文献溯源是 SKU 整体史料清单（不是单集参考资料），文献处理分为两个阶段：前置生成、大纲对照修订；另有可选的版本演进复盘。两个阶段共用同一份整体文献溯源文档，逐版升版，不覆盖旧版本。

write-source-tracing（文献溯源初版） 负责「从无到有生成初版」，内部四步执行：

  • Step 1 · 事件清单：把简案 12 集表拆成每集 3–7 个待溯源事件，产出清单稿供教研确认；
  • Step 2 · 文献 list：在清单基础上补主文献、补充文献、推荐版本和推荐依据；
  • Step 3 · 正文录入：按 3 集一批 录入原文、译文、出处、译文版本，写完一批停下等教研审；
  • Step 4 · 自查：完成 12 集后生成自查报告，覆盖人名地名、数字、引文起讫、译文版本、误入影视小说传说等风险点。

Skill 只生成 0.0 和自查报告，不自动生成 1.0——1.0（前期锁定版）由教研人工审核确认后形成。

上下游衔接：上游是 write-outline-brief（简案定稿）；下游是 write-outline-framework（完整大纲框架）。它不处理完整大纲后的修订，也不负责单集参考资料——这两项交给 revise-source-tracing（文献溯源修订） 和 write-episode-content（分集资料撰写）。

阶段二 · 大纲框架期
节点 4

完整大纲框架 0.0

大纲框架
启动时机
文献溯源前期锁定版已经形成。
对应 SOP
教研·AI大纲制作SOP.md
对应 Skill
write-outline-framework（完整大纲框架）
核心产出
上下五千年{N}·{SKU名}·大纲框架0.0.md
关键交叉点
完整大纲阶段不再对整个时期从零大面积检索，只对缺口、冲突、因果桥梁和高风险事实做定向补查；补查结果暂记入「待同步文献溯源调整项」附录，不直接改文献溯源。
SOP 与 Skill 分工

SOP 层强调完整大纲的两个上位输入必须都到位：已确认的大纲简案 + 文献溯源前期锁定版。任何要动简案或锁定版结论的调整，先说明、后确认，不能静默改。

write-outline-framework（完整大纲框架） 的核心能力：

  • 继承简案前三部分（时代特征、整体教学目标、编排思路），不另起主题；
  • 以文献溯源前期锁定版为主，只做定向补查；
  • 按秦汉大纲框架格式输出每集内容（## E{N}-{标题} → 教学目标表 → 故事梗概 → 【核心情节 N：小标题】 → 演绎注意引用块）；
  • 实际写作顺序：先写故事梗概，再从梗概提炼教学目标；最终输出仍按「教学目标→故事梗概→演绎注意」排列；
  • 0.0 允许比终稿更详细，方便教研后续删减；
  • 定向补查产生的新增、删除、修正、调整项记入附录「待同步文献溯源调整项」；
  • 完整大纲继续复核故事与整体目标的关系，但不强制每集设置情感目标。

上下游衔接：上游是 write-outline-brief（大纲简案） 和 write-source-tracing（文献溯源初版） 的锁定版；下游是完整大纲修订（人工为主）与 revise-source-tracing（文献溯源修订）。

对应 Skill

核心产出

关键交叉点
完整大纲修订到约 2.0、每集叙事边界稳定后，才启动文献溯源大纲对照修订。
SOP 与 Skill 分工

SOP 规定这一阶段的动作是「教研通读 0.0，删减冗余、补足断层、调整详略、纠正史实」。所有涉及换故事、调顺序、合并、拆分、改叙事中心的调整都要返回前序阶段处理，不能在完整大纲阶段静默改。新增史料和调整项继续记录在「待同步文献溯源调整项」中。审核、过稿和意见处理均由教研人工完成，不调用审阅 Skill。

上下游衔接：上游是完整大纲 0.0；下游同时接 revise-source-tracing（文献溯源二次修订）和完整大纲专家审核环节。

节点 6

文献溯源大纲对照修订 & 中期锁定

文献溯源
启动时机
完整大纲修订至约 2.0，故事、核心情节和叙事边界基本稳定。
对应 SOP
文献溯源协作SOP.md
对应 Skill
revise-source-tracing（文献溯源修订） 的「完整大纲对照修订」模式。
核心产出
{SKU名}-文献溯源-大纲对照调整清单.md → 教研确认后 → {SKU名}-文献溯源2.0.md（文内标注「中期锁定版」）。
关键交叉点
Skill 先出清单、后改文档——教研确认调整范围后，Skill 才写入新版本，不直接覆盖前期锁定版。
SOP 与 Skill 分工

SOP 层强调每次修订都是清单先行、确认后改，且清单不是最终交付——教研确认后需要把修订同步进整体文献溯源新版本。

revise-source-tracing（文献溯源修订）在本节点执行「完整大纲对照修订」模式：

  • 逐集读取完整大纲 2.0 的故事梗概、关键人物、时间、地点、制度、典故和结果；
  • 对照前期锁定版文献溯源，判断新增 / 删除 / 替换 / 调整位置 / 待确认五类调整；
  • 先产出调整清单供教研确认；
  • 教研确认后，Skill 直接写入整体文献溯源新版本，通常形成 2.0（中期锁定版）。

上下游衔接：上游是完整大纲 2.0 + 文献溯源前期锁定版；下游是完整大纲专家审核和分集资料阶段。

对应 SOP
教研·AI大纲制作SOP.md
对应 Skill
人工完成，不调用审阅 Skill。
核心产出

关键交叉点

SOP 与 Skill 分工

SOP 规定这一阶段：3.0 发专家 → 专家意见返回 → 修改为【终稿】 → 生成 HTML 并与石墨、Markdown 一起发出走制作评审 → 无大改则会后微调确认；有较大调整则形成带日期的更新终稿。审核、过稿和专家意见处理均由教研人工完成，不调用审阅 Skill；产生的新史料调整记入文献溯源调整记录。

上下游衔接：上游是完整大纲 2.0 + 文献溯源中期锁定版；下游是分集资料撰写。

分集资料
启动时机
SKU 大纲框架终稿完成、对应批次文献溯源已录入。
对应 SOP
教研·分集资料制作SOP.md
对应 Skill
write-episode-content（分集资料撰写） 的 Phase 2。
核心产出
{SKU名}·E{N}{标题}·分集资料0.0.md；一周 3 集，按 E1–3 / E4–6 / E7–9 / E10–12 四批推进。
关键交叉点
分集资料 0.0 / 1.0 / 1.x 阶段，第四节「参考资料」只放占位；进入约 2.0 后才启动配套单集参考资料。每集分集资料都必须设置情感目标，并明确对应的剧情落点。
SOP 与 Skill 分工

SOP 层规定分集资料的生产节奏：一周写 3 集，AI 生成 0.0 → 人工校准形成 1.0 → 内部第一次过稿后形成 2.0 → 内部第二次过稿并内部确定后形成 3.0 → 3.0 周三发专家 → 专家周五返稿 → 整理后周一将本批终稿一并发编剧、导演。全 SKU 12 集约 4 周写完 + 2–3 周审校交接。

write-episode-content（分集资料撰写） 的 Phase 2 负责撰写分集资料，能力包括：

  • 读取大纲框架、文献溯源和相邻集素材；
  • 先写故事梗概，再从梗概提炼教学目标；
  • 固定四节结构（教学目标 / 故事梗概 / 背景信息-专家提供 / 参考资料）；
  • 每集设置情感目标，并把情感目标落到具体情节、人物选择或结果上；
  • 故事梗概按「【故事主线】引用块 → 自然段正文 → 演绎注意引用块」版式，正文默认不加阶段性小标题；
  • 背景信息保留四列表格空框，人物名替换，其余留空供专家填写；
  • 第四节参考资料在 0.0 / 1.x 时只留占位，进入 2.0 后才替换为配套参考资料文档链接。

上下游衔接：上游是大纲框架终稿 + 文献溯源中期锁定版；下游是节点 9（单集参考资料）和节点 10（专家审核）。

SOP 与 Skill 分工

分集资料 SOP 规定参考资料在分集资料进入 2.0 后启动；它与整体文献溯源保持来源对应关系，但作为单集配套资料独立维护，不再回写整体文献溯源。

write-episode-content（分集资料撰写） 的 Phase 3 负责单集参考资料，两个固定部分：

  • 一、史料：先从整体文献溯源复制本集相关内容，再与当前分集资料 2.0 的教学目标、故事主线和故事梗概逐项对照，判断保留、删除、补充或待确认；保留原文、出处、译文，不用省略号裁剪；正文新增史实必须同步补入权威出处和译文；
  • 二、演绎参考：回收当前 task 中教研已确认、对编剧理解剧情有帮助的追问和细节；每条注明信史 / 后世记载 / 笔记 / 小说 / 戏剧 / 传说 / 演绎参考等资料性质，不混作信史。

上下游衔接：上游是分集资料 2.0 + 整体文献溯源中期锁定版；下游是节点 10（分集资料审核与终稿）。

design-questions（交互题出题） 内部按六阶段执行：

  • Phase 0 · 对照出题手册自查：强制步骤，对照手册 9 条原则、题型推荐映射表、不推荐题型、跨场景使用规则、8 种趣味性策略，产出对照自查清单；
  • Phase 1 · 开放思考 + 第一轮出题：每个考查点先自由发散 2–3 种方向，再回到题型库找最贴合的子题型；每考查点产出 1 推荐 + 1 备选（共 8 道）；
  • Phase 2 · 推荐 / 备选比选：按 P0（题型合适 + 考查点准确）> P1（题型丰富 + 趣味性高）> P2（避免过于明显的跨集重复）三级优先级复核；
  • Phase 3 · 全局质检：4 道推荐方案对照出题手册第七章 5 类清单 + P0/P1/P2 框架逐项检查；
  • Phase 3.5 · 表述优化：逐题逐句朗读题干语音、选项、操作指令、反馈语音，检查操作指令是否符合常理、动词搭配、指代清晰、儿童认知友好、逻辑通顺；
  • Phase 4 · 文档输出：每考查点 2 道题（推荐在前 / 备选在后），附 5 个附录。
